============================================================
1. PROJECT OBJECTIVE
============================================================

Implement an internally developed privacy, cookie consent and GDPR management system for soFlott UG.

The objective is to provide a professional, transparent and legally appropriate privacy experience without relying on a paid third-party Consent Management Platform (CMP).

The system must:

- Allow visitors to control optional cookies and tracking technologies.
- Prevent non-essential tracking before valid consent.
- Support Google Analytics 4 and , Facebook Pixel, Instagram Ad, LinkedIn Ads, Google Ads.
- Implement Google Consent Mode v2.
- Provide a persistent cookie settings interface.
- Store and manage consent preferences.
- Provide transparent privacy information.
- Support customer and business data protection.
- Support future expansion of the soFlott courier and digital services.

The implementation must follow applicable GDPR (DSGVO), German TDDDG and other relevant European data protection requirements.

IMPORTANT:
Technical implementation does not automatically guarantee legal compliance. Final legal documents, processing purposes, legal bases and consent mechanisms must be validated against the actual business operations.

3. COOKIE CONSENT CATEGORIES
============================================================

The consent manager must provide exactly four main categories.

3.1 NECESSARY

Status: Always enabled.

Purpose:
Essential technologies required for website functionality, security and service delivery.

Examples:
- Authentication and session management.
- CSRF protection.
- Security and fraud prevention.
- Essential application cookies.
- Consent preference storage.
- Load balancing and technical session functionality.

Users cannot disable genuinely necessary technologies through the consent interface.

Do not classify advertising or analytics technologies as necessary.

3.2 ANALYTICS

Status: Optional.

Purpose:
Understand website usage and improve the soFlott website and customer experience.

Examples:
- Google Analytics 4.
- Page views.
- Website traffic statistics.
- Navigation patterns.
- Traffic sources.
- Campaign performance.
- Conversion analysis.

Default state: Disabled until consent.

3.3 ADS & MARKETING

Status: Optional.

Purpose:
Measure advertising performance and support advertising-related functionality.

Examples:
- Google Ads conversion tracking.
- Google Ads remarketing.
- Advertising identifiers.
- Meta Pixel
- Instagram Ad
- LinkedIn Insight Tag
- Advertising campaign measurement.
- Enhanced conversions, where legally and technically appropriate.

Default state: Disabled until consent.

3.4 PREFERENCES

Status: Optional.

Purpose:
Remember user choices and improve website usability.

Examples:
- Preferred language.
- Non-essential display settings.
- Personalisation preferences.
- Optional interface settings.

Default state: Disabled until consent.

Essential language or accessibility functionality may be provided without consent where genuinely necessary and legally justified.

6. CONSENT MANAGEMENT LOGIC
============================================================

The system must support these actions:

FIRST VISIT:
- Check whether valid consent exists.
- If no valid consent exists, display the banner.
- Initialise necessary functionality only.
- Keep optional tracking blocked.

ACCEPT ALL:
- Enable all four categories.
- Update the consent record.
- Update Google Consent Mode signals.
- Load permitted tracking technologies.

REJECT OPTIONAL:
- Enable necessary functionality only.
- Keep analytics, advertising and optional preferences disabled.
- Update the consent record.

CUSTOMISE:
- Display category settings.
- Allow individual category selection.
- Save the selected categories.

RETURNING VISITOR:
- Read previously saved consent.
- Validate its version and expiry.
- Restore the selected preferences.
- Do not repeatedly display the banner when valid consent exists.

WITHDRAW CONSENT:
- Allow the visitor to reopen settings.
- Allow optional categories to be disabled.
- Update consent signals.
- Prevent future optional tracking.
- Remove or disable applicable optional cookies where technically possible.

CONSENT VERSION CHANGE:
- If the consent notice or relevant processing purposes materially change, invalidate the old consent where necessary.
- Request new consent.

7. CONSENT STORAGE
============================================================

Store the consent selection in a first-party cookie.

Suggested cookie:

Name:
soflott_consent

Suggested properties:

- Secure
- SameSite=Lax
- Appropriate expiry
- Path=/

Use a suitable retention period and renew consent when required.

Illustrative structure:

{
  "necessary": true,
  "analytics": false,
  "marketing": false,
  "preferences": false,
  "version": "1.0",
  "updatedAt": "2026-11-08T12:00:00Z"
}

This is an example data structure, not a complete legal consent record.

Requirements:

- Necessary must always remain true.
- Validate stored data before using it.
- Reject malformed or outdated consent data.
- Do not trust client-provided consent information for unrelated security decisions.
- Avoid storing personal information unnecessarily in the consent cookie.

Consent evidence should be maintained separately where required.

Possible consent evidence fields:

- Consent record identifier.
- Consent notice version.
- Timestamp.
- Selected categories.
- Consent action.
- Relevant consent configuration.
- Withdrawal timestamp, where applicable.

IP addresses and other identifiers should not be collected or retained unnecessarily. Determine the appropriate evidence and retention approach through legal review.

8. GOOGLE ANALYTICS 4 INTEGRATION
============================================================

Google Analytics 4 must only operate under the appropriate consent conditions.

Requirements:

- Do not initialise optional analytics tracking before consent.
- Do not send analytics events when analytics permission is absent.
- Do not collect unnecessary personal information.
- Do not send customer addresses, phone numbers, delivery instructions or payment information to GA4.
- Respect consent withdrawal.
- Configure data retention settings.
- Review Google Signals and advertising features separately.

The following Consent Mode signal must be controlled:

analytics_storage

Expected behaviour:

No analytics consent:
analytics_storage = denied

Analytics consent:
analytics_storage = granted

Use Basic Consent Mode initially.

Do not assume that setting a consent signal to denied automatically prevents every Google tag from loading. Optional tags must be blocked until the required consent has been obtained.

============================================================
9. GOOGLE ADS INTEGRATION
============================================================

Google Ads must be controlled independently from analytics.

Relevant Consent Mode v2 signals:

ad_storage
ad_user_data
ad_personalization

Expected behaviour without marketing consent:

ad_storage = denied
ad_user_data = denied
ad_personalization = denied

After valid marketing consent:

ad_storage = granted
ad_user_data = granted
ad_personalization = granted

Requirements:

- Block optional advertising tags before consent.
- Do not enable remarketing before appropriate consent.
- Do not upload customer lists without a separate legal assessment.
- Do not use delivery recipient information for advertising.
- Review enhanced conversions separately.
- Provide transparent advertising disclosures.

============================================================
10. GOOGLE CONSENT MODE V2
============================================================

Implement Google Consent Mode v2.

Relevant signals:

analytics_storage
ad_storage
ad_user_data
ad_personalization
functionality_storage
personalization_storage
security_storage

Suggested mapping:

NECESSARY:
security_storage = granted

ANALYTICS:
analytics_storage = granted only after consent.

ADS & MARKETING:
ad_storage = granted only after consent.
ad_user_data = granted only after consent.
ad_personalization = granted only after consent.

PREFERENCES:
functionality_storage = granted only after consent where applicable.
personalization_storage = granted only after consent where applicable.

Initial consent state must be established before optional Google tags can run.

Google tags must receive updated consent signals when visitors change their preferences.

The implementation must not use Consent Mode as a substitute for blocking optional tags in Basic Consent Mode.

13. DATA SECURITY
============================================================

Implement appropriate technical and organisational measures.

Recommended controls:

- HTTPS throughout the application.
- Secure password hashing.
- Role-based access control.
- Strong authentication for administrators.
- API authentication and authorisation.
- Rate limiting.
- Input validation.
- Protection against common web vulnerabilities.
- Secure database credentials.
- Encryption at rest where appropriate.
- Encrypted backups.
- Restricted production database access.
- Security monitoring.
- Appropriate audit logging.

Do not log:

- Passwords.
- Authentication tokens.
- Payment card details.
- Unnecessary customer personal information.
- Full delivery instructions unless operationally necessary.

Establish a data breach response procedure, including assessment and applicable GDPR notification deadlines.

============================================================

Different data categories require different retention periods.

Examples:

- Uncompleted enquiries.
- Customer account data.
- Booking and delivery records.
- Invoices and accounting records.
- Payment references.
- Security logs.
- Consent evidence.

Do not apply one universal deletion period to every record.

Accounting documents may need to be retained under German statutory requirements, even if a customer requests account deletion.

Provide procedures for:

- Account deletion requests.
- Personal data access requests.
- Data correction.
- Data export.
- Restriction of processing.
- Objection requests.
- Deletion where legally applicable.

Deletion should include relevant systems and backups according to the documented retention and backup lifecycle.
